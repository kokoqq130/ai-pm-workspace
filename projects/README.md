# 旧项目挂载区

这个目录专门用来挂载需要拿来对比分析的旧项目。

## 用法

- 如果你需要 AI 结合旧项目代码、目录结构、页面实现或历史文件来分析，请把旧项目挂载到这个目录下。
- 推荐目录格式：
  - `projects/旧项目名/`
  - `projects/project-a/`
  - `projects/legacy-admin/`

## 推荐挂载方式

优先使用目录联接（junction），不要直接把整个旧项目复制进来。

这样做的好处是：

- `projects/` 里看到的是旧项目入口，但不会复制一份物理文件
- 原项目还保留在原来的位置
- AI 可以读取这个入口下的内容
- 你不会因为“拖拽复制”搞出多份旧项目副本

推荐命令：

```powershell
.\mount-legacy-project.ps1 -SourcePath "D:\你的旧项目路径" -AliasName "旧项目名"
```

例如：

```powershell
.\mount-legacy-project.ps1 -SourcePath "D:\codes\kelingsys" -AliasName "kelingsys"
```

如果你正在当前工作空间里使用 Codex，也可以直接自然语言告诉 AI：

```text
把 D:\你的旧项目路径 挂载到 projects 里，名字叫 旧项目名
```

当前工作空间已经有本地 skill 会调用脚本处理这个动作。

## 推荐做法

1. 如果你已经有旧项目摘要，先把摘要、背景和关键结论写到 `.pm-workspace/references/旧项目名/`
2. 如果你没有摘要但已经有旧项目代码，可以先把旧项目挂载到 `projects/` 下
3. 让 AI 先基于旧项目生成摘要，再把这份摘要沉淀到 `.pm-workspace/references/旧项目名/`
4. 后续再同时查看：
   - `.pm-workspace/references/旧项目名/` 中的摘要
   - `projects/旧项目名/` 中的原始内容

## 什么时候需要真的挂载旧项目

以下情况建议把旧项目挂载到 `projects/` 下：

- 需要看真实页面或模块结构
- 需要看旧方案是怎么实现的
- 需要比较新想法和旧实现的差异
- 需要判断哪些能力能复用、哪些应该重做
- 需要基于旧项目继续做迭代规划

如果只是做业务判断、需求梳理或方向判断，通常先看摘要就够了，不必一开始就挂整个旧项目。
如果你当前没有摘要，但已经有旧项目代码，也可以先挂载项目，再让 AI 生成摘要。

## 如果你已经误拖成了真实复制目录

如果 `projects/旧项目名/` 已经变成一份真实复制的项目，不要继续往里面改。

更推荐的处理方式是：

1. 找到原项目的真实路径
2. 删除 `projects/` 下那份复制出来的旧项目
3. 改用 `mount-legacy-project.ps1` 创建目录联接

只有当你确认 `projects/` 下那份是复制出来的副本，而不是唯一原件时，才删除它。
