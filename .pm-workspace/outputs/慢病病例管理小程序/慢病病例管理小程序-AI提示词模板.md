# 慢病病例管理小程序 AI 提示词模板

## 1. 使用说明

本文档用于统一你在开发过程中调用 AI 时的提示词结构，减少输出风格不稳定、代码口径不一致和反复返工。

建议原则：

- 每次只处理一个明确目标
- 明确输入、输出、边界和约束
- 引用现有文档，不要让 AI 自己猜
- 先让 AI 出方案，再让 AI 出代码

## 2. 通用提示词骨架

```text
你现在是这个项目的协作开发助手。

项目背景：
- 项目名称：慢病病例管理微信小程序
- 技术栈：微信小程序原生 + TypeScript + 腾讯云 CloudBase + 腾讯云 OCR
- 主后端语言：Node.js
- 当前目标模块：[填写模块名]

请严格基于以下约束工作：
- 不要引入与当前模块无关的功能
- 不要做诊断、治疗建议、药物调整建议
- 保持字段命名和现有 schema 一致
- 优先复用 shared/types 思路

参考文档：
- PRD：[填写路径]
- 技术架构：[填写路径]
- 库表设计：[填写路径]
- 页面与接口设计：[填写路径]
- 交互说明：[填写路径]

本次任务：
[明确写出这次只做什么]

输出要求：
[明确让 AI 输出什么]

限制：
[明确不能做什么]
```

## 3. 模块设计提示词模板

适用场景：

- 先让 AI 输出模块方案
- 先确认再进入代码实现

模板：

```text
请基于现有项目文档，输出“[模块名]”的实现方案。

要求：
1. 先概述模块目标
2. 列出涉及的页面、云函数、数据表
3. 列出输入输出
4. 列出主要边界情况
5. 列出推荐的 TypeScript 类型
6. 不要直接写代码

当前模块：
[例如：OCR 结果确认页]

必须遵守：
- 不扩展需求范围
- 不改动现有核心字段命名
- 不把数据库类型和前端展示类型混用
```

## 4. 页面开发提示词模板

适用场景：

- 让 AI 生成小程序页面代码

模板：

```text
请为微信小程序原生 + TypeScript 项目实现“[页面名]”。

页面目标：
[填写页面目标]

页面结构：
[可直接贴低保真界面交互说明中的结构]

交互要求：
- [要求 1]
- [要求 2]
- [要求 3]

数据来源：
- 使用 [接口名/云函数名]

输出要求：
1. 给出页面目录建议
2. 输出 wxml / wxss / ts 代码结构建议
3. 如果代码较长，先给组件拆分方案
4. 不实现与本页面无关的功能

特别要求：
- 空状态、加载状态、失败状态都要考虑
- 文案保持克制，不要医疗化夸张表述
```

## 5. 云函数开发提示词模板

适用场景：

- 让 AI 生成 CloudBase 云函数

模板：

```text
请实现 CloudBase Node.js 云函数：[函数名]

函数目标：
[例如：根据 documentId 调用 OCR 并写入 OCR 结果]

输入：
[输入字段]

输出：
[输出字段]

涉及集合：
- [集合 1]
- [集合 2]

要求：
1. 使用 TypeScript 风格或接近 TypeScript 的结构
2. 加入必要的参数校验
3. 考虑失败场景
4. 保持和现有 schema 一致
5. 不要引入多余框架

还需要输出：
- 可能的错误码
- 关键日志点
```

## 6. 类型定义提示词模板

适用场景：

- 让 AI 生成 shared types

模板：

```text
请根据当前项目 schema，为以下模块生成 TypeScript 类型定义：
- [填写模块]

要求：
1. 区分 shared 类型、db model、dto、view model
2. 不要把所有类型合并成一个大 interface
3. 字段命名必须与现有文档一致
4. 输出按文件拆分建议
```

## 7. 测试用例生成提示词模板

适用场景：

- 让 AI 帮你写测试清单或测试代码

模板：

```text
请为模块“[模块名]”输出测试用例。

要求：
1. 按正常流程、边界场景、异常场景分类
2. 优先输出人工测试用例
3. 额外补充可自动化的测试点
4. 不要省略失败重试、空状态和删除联动
```

## 8. Code Review 提示词模板

适用场景：

- 让 AI 复查已经生成的代码

模板：

```text
请以代码评审模式审查以下改动。

重点只看：
- bug
- 状态流是否有缺口
- 数据结构是否和 schema 一致
- 删除联动和错误处理是否完整
- 是否超出首版范围

不要泛泛夸奖。
如果没有问题，也要指出剩余风险和测试缺口。
```

## 9. 任务拆分提示词模板

适用场景：

- 把一个大模块拆成可执行小任务

模板：

```text
请把“[目标模块]”拆成适合单人 + AI 协作开发的任务清单。

要求：
1. 任务粒度控制在 0.5 天到 1 天
2. 按依赖顺序排列
3. 标出 P0 / P1
4. 每个任务写清交付物
```

## 10. 推荐使用顺序

建议每个模块按以下顺序调用 AI：

1. 先用“模块设计提示词”
2. 再用“类型定义提示词”
3. 再用“页面开发/云函数开发提示词”
4. 然后用“测试用例生成提示词”
5. 最后用“Code Review 提示词”
