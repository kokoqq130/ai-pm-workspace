# 慢病病例管理小程序页面与接口补充设计

## 1. 页面清单

### 页面优先级

P0：

- 首页
- 患者列表页
- 患者详情页
- 上传资料页
- OCR 确认页
- 病例时间线页
- 就诊摘要页

P1：

- 用药记录页
- 设置与隐私页

### 1.1 首页

目的：

- 展示最近使用的患者
- 提供上传入口
- 提供最近生成的摘要入口

核心模块：

- 最近患者卡片
- 快速上传按钮
- 最近待处理资料列表
- 最近摘要入口

### 1.2 患者列表页

目的：

- 查看所有患者档案
- 创建新患者

核心模块：

- 患者卡片列表
- 搜索框
- 新建按钮

### 1.3 患者详情页

目的：

- 作为患者维度的总入口

核心模块：

- 基础信息
- 最近资料
- 时间线入口
- 用药记录入口
- 就诊摘要入口

### 1.4 上传资料页

目的：

- 上传图片或 PDF

核心模块：

- 选择患者
- 选择文件
- 上传进度
- 处理状态

### 1.5 OCR 确认页

目的：

- 让用户修正识别出的关键字段

核心模块：

- 原文预览
- OCR 文本
- 字段编辑区
- 保存按钮
- 重新识别按钮

### 1.6 病例时间线页

目的：

- 查看病情随时间变化

核心模块：

- 时间线列表
- 事件筛选
- 事件详情弹层

### 1.7 用药记录页

目的：

- 查看长期药物变化

核心模块：

- 当前用药
- 历史用药
- 添加/编辑按钮

### 1.8 就诊摘要页

目的：

- 为复诊或换医生提供简洁摘要

核心模块：

- 当前病情摘要
- 既往重要病史
- 当前用药
- 近期检查结果
- 复制/分享按钮

## 2. 页面流转

建议主流程：

1. 首页
2. 新建或选择患者
3. 上传资料
4. OCR 处理中
5. OCR 确认
6. 自动生成时间线
7. 查看患者详情
8. 生成就诊摘要

## 3. 接口/云函数清单

## 3.1 login

用途：

- 微信登录
- 创建/更新用户

输入：

```json
{
  "code": "wx_login_code"
}
```

输出：

```json
{
  "userId": "u_xxx",
  "openid": "openid_xxx"
}
```

## 3.2 createPatient

用途：

- 创建患者档案

输入：

```json
{
  "name": "父亲",
  "gender": "male",
  "birthYear": 1965,
  "diseaseTags": ["高血压", "糖尿病"],
  "allergyNotes": ""
}
```

## 3.3 listPatients

用途：

- 获取当前用户的患者列表

## 3.4 createDocument

用途：

- 创建上传资料记录

输入：

```json
{
  "patientId": "p_xxx",
  "fileType": "image",
  "sourceType": "upload",
  "filePath": "cloud://tmp/xxx.jpg"
}
```

## 3.5 runOcr

用途：

- 调用 OCR 并写入原始结果

输入：

```json
{
  "documentId": "d_xxx"
}
```

输出：

```json
{
  "status": "recognized",
  "ocrResultId": "ocr_xxx"
}
```

## 3.6 parseMedicalDocument

用途：

- 解析 OCR 文本并提取结构化字段

输入：

```json
{
  "documentId": "d_xxx"
}
```

输出字段建议：

- 文档日期
- 医院
- 科室
- 诊断关键词
- 药品列表
- 检查项目列表

## 3.7 updateStructuredResult

用途：

- 保存用户修正后的结构化结果

输入：

```json
{
  "documentId": "d_xxx",
  "structuredData": {
    "docDate": "2026-03-01",
    "hospitalName": "某医院",
    "departmentName": "心内科"
  }
}
```

## 3.8 rebuildTimeline

用途：

- 根据全部结构化结果重建某个患者的时间线

输入：

```json
{
  "patientId": "p_xxx"
}
```

## 3.9 listTimelineEvents

用途：

- 获取患者时间线事件

## 3.10 saveMedicationRecord

用途：

- 新建或编辑用药记录

## 3.11 generateVisitSummary

用途：

- 生成固定模板就诊摘要

输入：

```json
{
  "patientId": "p_xxx"
}
```

输出：

```json
{
  "summaryId": "s_xxx",
  "summaryText": "..."
}
```

说明：

- 首版默认支持文本复制
- 首版不强制支持 PDF 导出和图片分享

## 3.12 createManualRecord

用途：

- 在 OCR 失败时手工补录简版病例记录

输入：

```json
{
  "patientId": "p_xxx",
  "eventDate": "2026-03-01",
  "documentType": "门诊病历",
  "summary": "复诊，继续原有用药方案"
}
```

## 3.13 deleteDocument

用途：

- 删除资料记录及相关结构化结果

## 4. 状态字段建议

### documents.status

- `pending`
- `processing`
- `recognized`
- `parsed`
- `failed`

### visit_summaries.status

- `draft`
- `generated`
- `archived`

## 5. 首版验收重点

- 登录是否稳定
- 上传和 OCR 是否能闭环
- OCR 错误是否可修正
- OCR 失败时是否可通过手工补录继续完成流程
- 时间线是否可读
- 摘要是否真正能帮助复诊沟通
- 敏感资料删除是否可用
