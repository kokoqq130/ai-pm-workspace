# 三种需求场景提示词模板

这份文件是备用模板。

如果你懒得自己组织提示词，可以直接复制其中一个场景，填空后交给 Codex。
如果你更习惯自然语言，也可以不复制模板，直接描述场景即可。

## 场景一：已经有 PRD，想知道如何落地

```text
我已经有一份 PRD。

PRD 文件路径：
`<填写路径>`

请先不要直接输出开发排期。
先帮我判断这份 PRD 是否已经具备“可落地”的基本条件。

请按下面步骤处理：
1. 检查 PRD 是否缺少关键信息，例如目标用户、范围边界、依赖、验收标准、成功指标、里程碑。
2. 如果信息不足，先向我提最多 5 个最关键的问题。
3. 如果信息足够，请输出：
   - MVP 范围
   - 非本期范围
   - 关键依赖与风险
   - 建议的 epic 划分
   - 建议的用户故事拆分
   - 建议的落地顺序
4. 将分析过程写入 `.pm-workspace/analysis/<项目名>/`
5. 将最终落地建议写入 `.pm-workspace/outputs/<项目名>/`
```

## 场景二：只有一个想法，想完善成可以落地的 PRD

```text
我现在只有一个初步想法，还不是完整 PRD。

想法文件路径：
`<填写路径>`

请不要一开始就直接写完整 PRD。
先帮我把这个想法梳理成可以落地的需求。

请按下面步骤处理：
1. 先判断这个想法真正要解决的问题是什么。
2. 帮我识别目标用户、业务目标、核心假设、风险和边界。
3. 如果信息不足，先向我提最多 5 个最关键的问题。
4. 如果还需要做发现或验证，请先告诉我应该先验证什么。
5. 在信息足够后，再整理为：
   - 问题定义
   - 用户与场景
   - 目标与成功标准
   - 需求范围与非目标
   - 方案概要
   - PRD 草稿结构
6. 将分析过程写入 `.pm-workspace/analysis/<项目名>/`
7. 将整理后的 PRD 或 PRD 草稿写入 `.pm-workspace/outputs/<项目名>/`
```

## 场景三：有一个旧项目和一个新想法，想判断旧项目接下来该做什么迭代

```text
我有一个旧项目和一个新想法，想判断旧项目下一步应该做什么迭代。

旧项目摘要路径：
`<填写路径，没有就写无>`

旧项目目录路径：
`<填写路径，没有就写无>`

新想法路径：
`<填写路径>`

请按下面步骤处理：
1. 先判断当前是否已经具备足够信息。
2. 如果旧项目还没有挂载到工作区，请明确告诉我应该把旧项目以目录联接方式挂载到 `projects/旧项目名/`。
3. 如果旧项目已经挂载但还没有摘要，请先基于旧项目生成一份摘要。
4. 如果旧项目摘要不足，请告诉我还需要补哪些背景信息到 `.pm-workspace/references/<旧项目名>/`。
5. 在信息足够后，帮我输出：
   - 旧项目当前最值得继续解决的问题
   - 新想法是否真的匹配旧项目的现阶段问题
   - 哪些能力可以复用
   - 哪些部分应该重做或不要继续做
   - 建议的下一步迭代方向
   - 优先级排序和理由
6. 将分析过程写入 `.pm-workspace/analysis/<项目名>/`
7. 将最终建议写入 `.pm-workspace/outputs/<项目名>/`
```
